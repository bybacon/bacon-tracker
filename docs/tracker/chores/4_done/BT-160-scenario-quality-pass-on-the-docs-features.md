Title: Scenario quality pass on the docs features

**Description:**
Many docs feature scenarios stated a situation and an outcome with no action
in between, and some asserted how the page is built rather than what anyone
sees, such as reused components or attribute names. A reader of the spec
learns nothing from those. Giving every scenario an action and moving the
build constraints into the architecture story or the ADR leaves scenarios that
describe behaviour Ingo can check.
