Your plan, next to your code.

bacon-tracker is a project tracker that lives in your git repo. Your stories, bugs, chores and decision records are Markdown and Gherkin files, with a drag-and-drop board on top that runs on your machine. No database. No third-party service. Just files.

$ gem install bacon-tracker

MIT licensed · Ruby ≥ 3.3 · rubygems · changelog

Four stages, four directories

Your work moves through icebox → backlog → started → done. Each stage is a directory, so the folder a story's file sits in is its stage. Your backlog is a text file in priority order, and finished stories stay in done for good.

1_icebox/what you might do
commit →
2_backlog/what you'll do next
start →
3_started/what you're on now
done →
4_done/what you shipped

No sprints, no releases, no finish lines. It's made for ongoing product work, where you ship continuously. The way of working behind it is written up as the bacon flow.

Why a tracker in your repo

Your plan and your code share one history

A story, the change that delivers it, and the decision behind it land in the same pull request, and you review them together. Run git log on a story file and you see every move it made. Months later, you can still tell what you decided, when, and why.

Your agent just uses it

A coding agent reads and edits your stories the way it reads and edits your code: as files. No MCP server to run, no tool definitions eating its context, no API token to rotate. It picks up a story, works it, and moves it to done in the same diff you review.

It stays yours

Your plan never leaves your repository. It lives under your access rules and your backups, and goes wherever your repo goes. No seats, no plan tiers, no subscription.

Side note: the repo is the sweet spot, not a requirement. Your tracker is just a folder, so it also works in a repo of its own or in a plain directory with no git at all.

Work from wherever you are

The terminal, the board, Claude Code and your editor all change the same files, so you can switch between them whenever you like.

Rake
Create, commit, start, finish, edit and lint stories from your terminal. rake "story:start[APP-007]"
The board
Drag cards between stages, reorder your backlog, tick off subtasks, and browse your docs and decisions. It runs on your computer, and nobody else can reach it.
Claude Code
Tell Claude what you want with the /tracker command, in your own words: /tracker new bug crash on empty cart, /tracker next.
Your editor
Stories are Markdown, features are Gherkin. Open them, change them, commit them.
Menu bar
On macOS, BaconTrackerMenu starts the board for you and keeps every project one click away.

Your first story on a board in five minutes

gem install bacon-tracker

tracker-init --path ./my-app --namespace APP --title 'My App' --yes

NS=APP rake "story:feature[My first story]"   # APP-001 in the icebox
NS=APP rake "story:commit[APP-001]"           # icebox → backlog

tracker-dashboard --dashboard dashboard.md    # open localhost:4567

Then run git diff: everything you just did shows up as an ordinary change. The README covers the two setup modes, the story format, linting in CI and the HTTP API. Want to look around first? The repo comes with a demo tracker you can run.
